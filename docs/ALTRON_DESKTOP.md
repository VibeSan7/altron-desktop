# Altron Desktop 0.3 — использование и возврат

## Установка

Используйте архив `altron-0.3.0-beta.1.tar.gz` из GitHub Releases, не ZIP исходников. В официальном Desktop выберите импорт профиля рядом с кнопкой `+`. Импорт создаёт профиль `altron`; существующий профиль не перезаписывается. Если имя занято, импорт откажет: откройте уже существующий профиль и сохраните его. Штатная кнопка импорта в проверенном Desktop не предлагает переименование архива. Не удаляйте старый профиль для обхода конфликта.

После импорта полностью закройте и снова откройте Desktop: он обнаружит Desktop-часть нового пакета. Во «Возможности → Плагины» включите переключатель **Desktop: Altron**, затем выберите профиль **`altron`** в панели профилей. В нём Python-плагин уже включён. Важно выбирать `altron` и после следующих перезапусков, прежде чем открыть вкладку Altron; профиль `default` не перенастраивается. Откройте Altron кнопкой в нижней строке или командой «Открыть Altron» в палитре команд. Если кнопки нет, используйте штатную команду Reload desktop plugins; не меняйте исходники Hermes.

Файл профиля содержит только объявленные файлы приложения. Он не содержит `.env`, `auth.json`, базы данных, логи и старые проекты. При первом открытии Altron создаёт свою пустую базу в выбранном профиле.

## Первый проект

1. Создайте отдельную папку проекта в Проводнике.
2. В Altron укажите название и полный путь. Не выбирайте весь диск или папку настроек Hermes.
3. Добавьте задачу и критерии готовности: что именно должно появиться и как это проверить.
4. Запишите план или явно запустите Altron для составления плана.
5. Согласуйте план, выберите роль, модель и подключение; подтвердите запуск в показанном диалоге.

Подключение модели настраивается в Hermes, не в Altron. Поле «Провайдер» — идентификатор подключения, например `openai-codex`, а не секрет. Запуск может тарифицироваться вашим провайдером. Altron не обещает бесплатный доступ и не меняет модель при отказе.

## Команда

Откройте «Состав команды» в проекте. Назначьте модель и подключение нужным ролям; при желании выберите адаптированные инструкции специалиста. Состав сохраняется для проекта.

В новой задаче заполните план и откройте «Последовательность специалистов». Добавьте шаги: роль, ожидаемый результат и критерии. После согласования отдельно подтвердите запуск команды. Например: технический исполнитель создаёт файл, специалист документации читает его и пишет инструкцию. Следующий шаг начинается лишь после проверяемого файла и завершающего сообщения Hermes. Проверяющий не добавляется скрыто; приёмка остаётся отдельным действием пользователя.

Пауза блокирует дальнейшие шаги. Прерванный или неподтверждённый запуск автоматически не повторяется. После перезапуска продолжение между завершёнными шагами требует явного подтверждения.

## Обновление и возврат кода

Начиная с 0.3 откройте «Обслуживание Altron»:

1. Завершите работу во всех окнах Altron; активные и неподтверждённые задачи блокируют обновление.
2. Скачайте архив и `SHA256SUMS.txt` из **одного** выпуска GitHub. Используйте только доверенный выпуск: контрольная сумма выявляет повреждение, но не делает неизвестный код безопасным.
3. Скопируйте полный путь архива из Проводника и 64 символа контрольной суммы из строки для этого архива. Ключи аккаунтов сюда не вводятся.
4. Нажмите «Проверить пакет», прочитайте версию и подтвердите установку. До подтверждения установленные файлы не меняются. Hermes может закрыть вкладку при перезагрузке плагина: снова нажмите Altron и откройте «Обслуживание», чтобы увидеть состояние.
5. Полностью закройте и снова откройте Hermes Desktop. До настоящего перезапуска новые задания заблокированы.
6. Для возврата выберите «Вернуть предыдущий код», подтвердите и перезапустите Desktop ещё раз. Текущая база проектов **не откатывается**. Локально изменённый код и повреждённая копия блокируют возврат вместо перезаписи.

Резервная копия базы и затронутого кода находится внутри профиля: `altron/maintenance/backups/`. Не удаляйте блокировки обслуживания вручную, если операция прервалась. Сначала сохраните профиль и выясните причину. Профиль 0.2 ещё не имеет этой панели; повторный импорт поверх него запрещён. Для перехода используйте отдельный профиль `altron-maintenance`: [инструкция обновления и возврата](https://github.com/VibeSan7/altron-desktop/blob/main/docs/UPDATING.md).

## Результат

Исполнитель получает только назначенную задачу через инструменты Altron. Он должен создать реальные файлы и передать относительные пути через `altron_update`. Altron читает файлы, сохраняет размеры и контрольные суммы. Это подтверждает существование и неизменность, но не качество содержания.

Проверьте файлы самостоятельно или отдельно запустите проверяющего. Затем опишите, что проверили, и нажмите «Я проверил результат — принять». Исполнитель не может принять свою работу этой командой.

## Ошибки и остановка

- **Остановлено с ошибкой:** Hermes закончил запуск ошибкой либо не передал проверяемый результат. Подробности доступны в диалоге.
- **Состояние не подтверждено:** соединение или процесс прервался; повторной отправки нет. Проверьте диалог до любого нового запуска.
- **Запрошена остановка:** запрос отправлен, но фактическое завершение ещё не подтверждено.
- **Выполнение остановлено:** получено завершающее сообщение Hermes об остановке.

Неопределённость не превращается в «готово». Для новой попытки после выяснения причины создайте отдельную задачу с новым явным согласованием; исходная запись сохраняется.

## Возврат к прежней работе

1. Запросите остановку активной задачи и проверьте её диалог.
2. Выключите Desktop: Altron в управлении плагинами и переключитесь на прежний профиль Hermes.
3. Сохраните профиль `altron`: в нём находятся задачи и решения. Для остановки работы не требуется его удалять.

Архив не заменяет `default`, старый Registry или исходники Hermes. Штатный экспорт профиля остаётся дополнительной страховкой. Desktop-часть общая для профилей; не перезаписывайте её вручную при конфликте версий. Обслуживание разрешает только совместимый формат данных 1; миграция старого Registry не выполняется.

## Проверенный предел

Проверена работа в установленном Windows 11 / Hermes Desktop 0.21.3 и его API. Это не испытание установки самого Hermes на чистом компьютере. Дополнительно проверено успешное задание через существующее подключение `openai-codex / gpt-6-astra`, с созданием реального файла и программной проверкой перед приёмкой. Первый вход нового аккаунта не проверялся. Штатные подключения остаются ответственностью пользователя. Точные границы указаны в [отчёте](https://github.com/VibeSan7/altron-desktop/blob/main/docs/DESKTOP_VERIFICATION.md).
